# Performance

Generated by `python scripts/bench.py`. Each operation ran 20 times after one warm-up, in-process on a throw-away database holding 166 audit entries. Python 3.11.9 on Windows 10.

| Operation | Median | 95th percentile | Slowest |
|---|---:|---:|---:|
| Sign in (argon2id password check) | 64 ms | 66 ms | 67 ms |
| Issue a prescription (sign + PDF + risk) | 151 ms | 172 ms | 177 ms |
| Verify a QR code | 19 ms | 22 ms | 22 ms |
| Verify an uploaded PDF (page check) | 1421 ms | 1461 ms | 1510 ms |
| Verify the whole audit chain | 25 ms | 30 ms | 32 ms |

These show how heavy each step is on one machine. They are not a capacity claim: the demo is one process on SQLite, and a network adds its own time. The slow steps are slow on purpose or by nature: argon2id is deliberately costly to make password guessing expensive, and verifying the audit chain re-computes every entry.
